<div style="opacity:0.8;margin-top:4px;">Fiche technique de référence</div>

<div style="background:#ffffff;border-radius:8px;border-left:4px solid #1d4ed8;padding:16px 20px;margin-bottom:16px;">
<div style="color:#1e40af;font-weight:bold;font-size:1.2rem;margin-bottom:10px;">🎯 Le problème résolu par l'AOP</div>
<div>Certaines préoccupations (logging, sécurité, transactions, cache, mesure de performance) sont dites <b>transversales</b> ("cross-cutting concerns") : elles traversent plusieurs couches et classes métier sans appartenir à une seule responsabilité. Les implémenter directement dans le code métier viole le principe de séparation des responsabilités et génère du code dupliqué ("code tangling").</div>
<div style="margin-top:10px;">L'AOP permet d'externaliser ces préoccupations dans des modules séparés appelés <b>aspects</b>, appliqués automatiquement au code métier sans le modifier.</div>
</div>

<div style="color:#1e40af;font-weight:bold;font-size:1.2rem;margin-bottom:10px;">⚙️ Spring AOP : caractéristiques clés</div>
<div>Spring AOP est une implémentation <b>proxy-based</b> et <b>runtime</b> de l'AOP, plus limitée mais plus simple qu'AspectJ complet (que Spring peut aussi intégrer pour du weaving compile-time/load-time).</div>
<table style="width:100%;border-collapse:collapse;margin-top:10px;">
<tr style="background:#eff6ff;color:#1e3a8a;border-bottom:2px solid #bfdbfe;">
<td style="padding:8px;font-weight:bold;">Aspect</td>
<td style="padding:8px;font-weight:bold;">Comportement Spring AOP</td>
</tr>
<tr style="background:#ffffff;">
<td style="padding:8px;">Mécanisme</td>
<td style="padding:8px;">Proxy dynamique (interception d'appel de méthode)</td>
</tr>
<tr style="background:#fafafa;">
<td style="padding:8px;">Join points supportés</td>
<td style="padding:8px;">Uniquement les appels de méthode (pas de field access, constructeur, etc.)</td>
</tr>
<tr style="background:#ffffff;">
<td style="padding:8px;">Portée</td>
<td style="padding:8px;">Uniquement les beans gérés par le conteneur Spring</td>
</tr>
<tr style="background:#fafafa;">
<td style="padding:8px;">Type de proxy</td>
<td style="padding:8px;">JDK dynamic proxy (si la classe implémente une interface) ou CGLIB (sous-classe, si pas d'interface)</td>
</tr>
</table>

<div style="background:#ffffff;border-radius:8px;border-left:4px solid #1d4ed8;padding:16px 20px;margin-bottom:16px;">
<div style="color:#1e40af;font-weight:bold;font-size:1.2rem;margin-bottom:10px;">💻 Exemple : aspect de logging</div>

```java
@Aspect
@Component
public class LoggingAspect {

    private static final Logger log = LoggerFactory.getLogger(LoggingAspect.class);

    @Pointcut("execution(public * com.example.service..*(..))")
    public void serviceLayer() {}

    @Around("serviceLayer()")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long duration = System.currentTimeMillis() - start;
        log.info("{} exécuté en {} ms", joinPoint.getSignature(), duration);
        return result;
    }
}
```

<div style="margin-top:10px;">Activation nécessaire dans une classe de configuration :</div>

```java
@Configuration
@EnableAspectJAutoProxy
public class AopConfig {
}
```

<div style="background:#f0fdf4;color:#166534;padding:10px 14px;border-radius:4px;margin-top:10px;">Résultat : chaque appel de méthode publique dans <span style="background:#e0e7ff;color:#1d4ed8;padding:1px 5px;border-radius:3px;">com.example.service</span> est chronométré et loggé sans qu'aucune classe métier ne soit modifiée.</div>
</div>

<div style="background:#fef9c3;border:1px solid #fde047;color:#713f12;padding:14px 18px;border-radius:6px;">
<div style="font-weight:bold;margin-bottom:6px;">⚠️ Limitations importantes de Spring AOP</div>
<div>• <b>Self-invocation</b> : un appel interne (<span style="background:#fef08a;padding:1px 5px;border-radius:3px;">this.methode()</span>) depuis la même classe ne passe pas par le proxy, donc l'advice ne se déclenche pas</div>
<div>• Ne fonctionne que sur les <b>méthodes publiques</b> des <b>beans Spring</b> (pas les objets créés hors conteneur, ni les méthodes privées/statiques)</div>
<div>• Avec <b>CGLIB</b>, impossible de proxyfier une classe <span style="background:#fef08a;padding:1px 5px;border-radius:3px;">final</span> ou des méthodes <span style="background:#fef08a;padding:1px 5px;border-radius:3px;">final</span></div>
<div>• Léger surcoût de performance dû à l'indirection du proxy (généralement négligeable)</div>
<div>• Pour un AOP plus complet (constructeurs, champs, weaving compile-time), il faut passer à <b>AspectJ complet</b> avec un compilateur ou agent dédié</div>
</div>
